# Governance

KumiUI follows a lightweight governance model:

## Core team
The core team consists of:
- [Your name] – design‑system engineer
- [Designer name – optional]

The core team is responsible for:
- Reviewing and merging PRs
- Publishing releases
- Making final decisions on component API
- Maintaining the token layer and Figma sync

## Decision making
- For minor changes (patch/minor), one core team approval is sufficient.
- For major changes (breaking), two approvals are required and a migration guide must be provided.
- Community feedback is collected via GitHub Discussions before large API decisions.

## How to become a core team member
- Consistent contribution over 3 months (PRs, reviews, discussions).
- Demonstrated understanding of accessibility and design token usage.
- Nominated by an existing core member.

## Communication
- All technical decisions are recorded in GitHub Discussions or ADRs (Architecture Decision Records).  
- Release notes are automatically generated from changesets.
